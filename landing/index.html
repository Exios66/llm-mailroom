The LLM-Mailroom

A multi-agent pipeline that ingests, classifies, extracts, and archives legal documents — with a full audit trail.

One LangGraph state machine per document. Specialist LLM agents per document class. Hash-chained audit log. Provider-agnostic LLM layer. Traced end-to-end.

    Route of a letter

    From inbox to archive

    The happy path costs two LLM generations. Everything else is procedural, gated, or a human's call.

    1. Intake

      The watcher claims the upload by atomic rename into processing/, transcribes it, and cleans it. Nothing is ever truncated.

    2. Classify

      The sorter picks one of five classes. At 0.97 or above it goes straight on; between 0.88 and 0.97 it goes to review.

    3. Extract

      The class specialist fills its schema. Guardrails check the JSON before anything moves forward.

    4. Verify

      Ambiguous extractions get a judge, then an arbiter. Conflicts go to the boss agent or a human.

    5. Archive

      A procedural report, a catalog row in SQLite, and an archive entry sealed into the hash-chained audit log.

    In the satchel

    What ships with it

    Five document classes
    Contracts, merger agreements, corporate records, correspondence, and insurance claims, each with its own specialist.
    Any model provider
    OpenRouter, Ollama, or vLLM. Agents ask for a role; taxonomy.yaml decides the model.
    Traced end to end
    Langfuse, Braintrust, or a local Arize Phoenix. The pipeline runs fine with none of them.
    Evaluation built in
    A 23-sample pilot with ground truth, deterministic field scoring, LLM judges, and a LegalBench harness.
