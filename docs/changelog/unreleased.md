## Added

- **Guarded autoresearch loop.** `experiments/autoresearch/objectives.yaml` registers each hill-climb objective (`thresholds`, `scale`, `review`) with its metric, direction, minimum gain, guards and the evidence a kept change needs; `src/scripts/autoresearch_gate.py` runs the core guards (compileall, affected tests, the experiment gate, the display contract, the changelog check) before the objective's eval, then keeps, discards or rejects the iteration (exit 0 / 3 / 2, 1 on crash) and logs it to `experiments/autoresearch/state/`. The `thresholds` objective also requires the paired-bootstrap ΔU interval to exclude 0. Protocol: `experiments/autoresearch/instructions.md`.
- **Scale hill-climb harness.** `src/scripts/stress_test.py` runs mock-LLM throughput, watcher backpressure, stale-claim, crash-recovery, SQLite-contention and provider-fault scenarios, gates on lost documents, duplicate rows, broken or missing audit entries and hijacked claims, and prints one `SCORE:` line.
- **A human review decision now flows back into the graph as data.** `POST /review/{doc_id}/resolve` accepts `resolution` (`approve_as_is` | `correct` | `reclassify` | `reject`) with `field_corrections`, `reviewer` (or the `X-Reviewer` header) and `reject_reason` (`not_a_legal_document`, `duplicate`, `unreadable`, `out_of_scope`, `wrong_matter`, `spam`, `other`). Approved or corrected fields go through the normal tail (`human_review` -> `compile_report` -> `catalog_write` -> `archive`) with no LLM call, so the report, catalog row, scores and `archived` audit event exist; the new `human_review -> compile_report` edge is gated on `review_decision == "human_applied"`, and a restart (no live checkpoint) enters at `compile_report` through the START router. Legacy `decision` + `disposition` requests still work: `approved`+`resume` re-extracts, `rejected`+`resume` rejects, `approved`+`complete` is `correct` (posted `extracted_data` replaces the parked fields) or `approve_as_is`. The manifest gains `human_label` (decision, resolution, final class, field corrections, a snapshot of the model output taken before the override, reviewer, UTC time, notes, reject reason), `extraction_source: "human"`, `reject_reason` and `file_location`; one `review_resolved` audit entry (actor = reviewer) precedes the tail. `extraction_confidence` stays the model's own value, never 1.0.

## Fixed

- **Audit writes survive heavy SQLite contention.** `write_audit_entry` retries `database is locked` on `BEGIN IMMEDIATE` with jittered backoff; each attempt re-reads the chain tail. At 128 writer threads failed operations drop from 119 to 0 with no broken chain.
- **Failed extraction chunks no longer archive silently, and chunk confidence is the weakest window's.** `BaseAgent.extract_chunked` (corporate record, correspondence, insurance) and the vendored `_SpecialistBase.extract_chunked` (contracts, merger) swallowed every per-chunk error and merged confidence as the MAX, so four windows `[0.98, ConnectionError, parse error, 0.4]` returned 0.98 with partial keys and auto-archived without a judge. A transient provider error in a window is now re-raised, so the node's `transient_error` routing retries it. A window that fails to parse (or raises a non-transient error) is counted: the result carries `_n_chunks` / `_failed_chunks` (underscore keys, ignored as non-public) and its confidence is capped strictly below the class `low` threshold, so routing retries or escalates. Merged confidence over the surviving windows is now the MIN, not the MAX. Single-window documents are unchanged. **Comparability:** long documents whose windows differ in confidence now score lower, and more of them reach retry or judge.
- **Sorter window disagreement now lowers confidence.** `_merge_sorter_reads` averaged only the windows that agreed with the winning class, so `[contract .99, corporate_record .99, correspondence .99]` merged to `contract .99`, and one `contract` window beside four `unknown` windows did too. Confidence is now the agreeing windows' mean times the share of non-unknown windows that agree (the first case reads 0.33), and when the winner holds fewer than half of all windows (unknown included) it is also capped strictly below its class `low` threshold. The vote vector rides the merged read as `_window_votes`. Single-window documents are unchanged. **Comparability:** over-budget documents with split window reads now reach retry or review where they used to continue.
- **A matter conflict no longer bypasses the extraction quality gates.** `after_extraction` sent `conflict_detected` straight to `boss_escalation` before the schema, hollow, coverage and confidence checks, and `after_boss` "approved" goes to `compile_report`, so a conflicted extraction with confidence 0.1 and an invalid schema was approved and archived with no retry, judge or review. The conflict check now runs at the point a sound extraction (schema valid, not hollow, coverage met, confidence at or above `low`) would otherwise go to `compile_report`; a failing extraction retries or escalates exactly as it would without a conflict. Return types and edge maps are unchanged.
- **Matter conflict detection no longer fires on formatting differences.** `_detect_conflict` compared normalized text for exact equality, so `Delaware` vs `State of Delaware` and `2024-01-05` vs `January 5, 2024` escalated to the Boss. Complete dates now compare as calendar dates (a bare year or month is not a date, and an ambiguous `01/02/2024` stays a text comparison); jurisdiction-like fields (`governing_law`, `jurisdiction`, `dispute_forum`, `venue`, court) ignore filler words (`state of`, `the`, `commonwealth`, `laws`) but still differ on any name part, so `Virginia` vs `West Virginia` and `State of New York` vs `State of New Jersey` remain conflicts; list fields are equal when one normalized set contains the other. The Dojo's `score_field` was tried and rejected for this: it scores `State of New York` vs `State of New Jersey` at 0.92, which a 0.9 cutoff would have hidden.
- **`_transient_decision` no longer claims the transient counters reset on success.** They never did, and must not: `first_pass_success` reads `transient_retries_<node>` to keep a document that needed a provider retry out of the first-pass KPI. The docstring now says so and a test pins it. Known limit: the budget is cumulative per node per run, so a node revisited several times (`retry_extract` through the arbiter loop) shares one budget of 2 transient retries.
- **Watcher concurrency is bounded.** Every watchdog event, startup-scan file and rescan tick used to start its own pipeline thread (400 inbox files ran 400 pipelines at once). Files now wait in a de-duplicated queue served by `watcher.max_concurrent_docs` workers (taxonomy.yaml, default 4; env `MAILROOM_MAX_CONCURRENT_DOCS`). `Watcher.stop()` discards files that have not started; they stay in the inbox. Needs a watcher/API restart.
- **Stale-claim reconcile no longer hijacks in-flight documents.** `claim_file` / `requeue_from_review` stamp the claim time (the hard link kept the upload's old mtime, so a document that waited in a backlog looked orphaned at once), and the periodic reconcile skips files this process is running or has queued.
- **Catalog writes are race-free upserts.** `write_matter_record` / `write_document_record` use one `INSERT ... ON CONFLICT DO UPDATE` (SQLite and PostgreSQL; other dialects keep the old path), so concurrent runs no longer fail with `UNIQUE constraint failed` and drop the stage update. Transient SQLite `database is locked` errors are retried with jittered backoff, and `busy_timeout` is now set before the WAL pragma (`SQLITE_BUSY_TIMEOUT_MS`, default 5000).
- A rejected review now resolves its interrupt checkpoint instead of leaking it, and a failed move to `failed/` is logged and recorded on the manifest (`file_location`) instead of swallowed.
- Resolving the same document twice (concurrently or late) returns a clean HTTP 409 instead of racing or a 400 with an enum repr; manifests are written atomically (temp file + `os.replace`).
- `human_review_node` no longer raises `UnboundLocalError` when the state has no `file_path`.
- **Every route into human review now names its cause.** `collect_review_causes` rebuilds the park reason from routing state (no ground truth or Langfuse scores needed) with new tokens `transient_exhausted`, `boss_conflict`, `arbiter_escalated`, `classification_arbiter_escalated`, `unknown_class`, `empty_document`, `unsupported_extraction`, `low_extraction_confidence`, `judge_incomplete`, `judge_error`, `retries_exhausted` and `chunk_failed`. `schema_invalid` and `guardrail` now fire from state. A judge `incomplete` verdict is `judge_incomplete`, no longer `reporting_incomplete`. Existing tokens are unchanged; The-Mailroom's `mailroom_ui/reconsideration.py` mirror needs the new ones.
- **Review tray is ordered by priority, then age.** `GET /review/queue` sorts by `pipeline/review_priority.py` (cause weights x class weight x age, from the new `review_queue:` block in `taxonomy.yaml`) and adds `priority`, `sla_breached` per item plus `oldest_age_hours` and `sla_breached` totals. Existing fields are unchanged.
- **Human resolutions become calibration labels.** `src/scripts/export_review_labels.py` turns manifests carrying a `human_label` into `RunRecord` JSONL (`gold.label_source="human"`) and prints wasted-review rate, correction rate, per-class agreement and field-edit counts. `Gold` gains optional `human_*` fields and `to_review_record` emits `human_decision`, `human_doc_type`, `human_doc_subclass`.
