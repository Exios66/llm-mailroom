## Changed

- **HF pilot, report re-scoring and calibration sweep score dataset labels only.** `run_hf_pilot` scores each row, and `enrich_sample_row` re-scores a stored report, against the fields whose source is `hub` (`labelled_fields`); post-hoc regex fills stay on the row (`expected_fields`, now with `expected_fields_sources`) for routing coverage. `run_calibration_sweep` gold is filtered the same way. A stored row without `expected_fields_sources` keeps scoring every stored field.
- **Interim llm-dojo-scoring pin `74b532a` (head of the unmerged Dojo PR stack #136 + #138 + #139, after v0.28.1; re-pin to the merge commit once it lands).** Brings in llm-dojo-scoring#139 (scoring fixes D1-D4, plus its review fixes: a CMS row's omitted documented-absent field still counts a stated value as a false positive, a batch row with no expected fields adds no events, and blank list items such as `denial_reasons: [None, ""]` on a CMS row are silence) so the grounded-scoring fixes in this branch run against them. The vendored fallback snapshot (`vendor/llm-dojo-scoring/`) is refreshed to the same commit (5 package files change since `f95c318`: `extraction_metrics`, `suites`, `metric_meta`, `registry`, `score_changelog`). **Scores that move (Dojo 0.29.0 score-change ledger, `rescore_required`):** `pipeline.extraction.field_micro_{precision,recall,f1,f2}` exclude a schema field the ground truth does not label, on both sides, so a correct value there is no longer a false positive (off-schema keys and values on a field labelled empty still are); a row with no labelled extraction field (presence-only CUAD, MAUD-only merger, no ground truth) reports them as null, not 0.0; a MAUD-only merger payload's headline `metric_id` is `maud.question.micro_accuracy`; a blank or literal `"nan"` `content_topic` / `sentiment_label` emits no topic or sentiment score instead of 0.0. Re-score stored runs before comparing them with older ones, with `get_suite(<agent>).score_document(expected=..., predicted=...)` (bare `score(...)` returns no field-micro for a single document). No Dojo release is cut yet.
- **Interim llm-dojo-scoring pin `4681148` (head of the unmerged Dojo PR stack #136 + #138, after v0.28.1; re-pin to the merge commit once it lands).** Brings in llm-dojo-scoring#136 (production slim-down) and #138 (CUAD per-category counts). The vendored fallback snapshot (`vendor/llm-dojo-scoring/`) is refreshed to the same commit by replacing the package tree, so the deleted files are gone. **Scores that move:** `parse_money("1.2M USD")` and `"USD 1.2M"` now parse (1200000.0) where they were `None`, and a carrier insurance extraction that states no `cms_source_table` is no longer penalised for it (a perfect one scored 0.9412), so money fields and `pipeline.extraction.overall` on carrier claims score higher, and `pipeline.extraction.field_micro_{f1,f2,precision,recall}` move with them, than under `f95c318`. Re-score stored runs before comparing them with older ones. There is no packaged rescoring CLI. To re-score a stored extraction run, load each document's stored expected and predicted values, call the extraction suite's `get_suite(<agent>).score_document(expected=..., predicted=...)` again (it returns the field-micro precision, recall, F1 and F2 that a bare `score()` call leaves out), and store the new result alongside the old one so the two scorer versions stay comparable (`score_document` accepts extraction suites only; re-score classification runs with `get_suite(<agent>).score(...)`). No `src/scripts` tool does this for you. **Removed upstream, unused here:** the `dojo-analyze`, `dojo-export`, `dojo-rescore` and `dojo-sync` CLIs, the workbook/report/grid modules, the Langfuse and Phoenix pull modules and `scoring.rescore`; the package root is now lazy (PEP 562), and `ExtractionSchema.schema_id` embeds the dataset tag (`@v9.3`, the revision this repo already pins). Every `llm_dojo_scoring` module path and root name that `src/` and `tools/` import still resolves, and the suite passes on the pinned release. Because the root is lazy, importing it no longer proves its scorers import, so `src/dojo_source` now resolves every name in `REQUIRED_ROOT_NAMES` (the root names `src/` and `tools/` import) inside its fallback boundary: an installed Dojo with a broken backing module, or one missing a required name, falls back to the vendored snapshot at import time instead of failing later (for example at `from llm_dojo_scoring import warm_embedding_model` in `api/main.py`). The two repo-guide pages for the Dojo no longer list the deleted CLIs or the removed grid-report guide. No Dojo release is cut yet.

Fully dated pairs score as before. ## Added

- **`run_pilot.py` runs on real documents from the pinned HF corpus.** `--dataset {samples,hf}` (with `--per-class`, `--seed`, `--split`) builds the pilot set from `Lucius-Morningstar/mailroom-dataset` through `hf_corpus_loader.load_corpus` at the pinned revision and writes each document's full text into the run's base dir. In `--mock`, a checkout without `docs/examples/samples/manifest.csv` falls back to it; `--real` needs `--dataset hf` named explicitly. Corpus rows count as real samples.
- **Guarded autoresearch loop.** `experiments/autoresearch/objectives.yaml` registers each hill-climb objective (`thresholds`, `scale`, `review`) with its metric, direction, minimum gain, guards and the evidence a kept change needs; `src/scripts/autoresearch_gate.py` runs the core guards (compileall, affected tests, the experiment gate, the display contract, the changelog check) before the objective's eval, then keeps, discards or rejects the iteration (exit 0 / 3 / 2, 1 on crash) and logs it to `experiments/autoresearch/state/`. The `thresholds` objective also requires the paired-bootstrap ΔU 95% interval to have a positive lower bound. Protocol: `experiments/autoresearch/instructions.md`.
- **Threshold calibration and offline route replay.** `src/schemas/run_record.py` defines a per-document `RunRecord` (every sorter, reviewer, extraction, judge and arbiter attempt, gold kept out of the routing state); `src/scripts/run_calibration_sweep.py` collects them with every sorter, reviewer and extraction branch run per document; the arbiter and Boss nodes are never run, and by default the judge runs only on extraction attempt 1 (`--judge-attempts all` judges every attempt) (`--real` refused unless `MAILROOM_ALLOW_REAL=1`). `src/scripts/calibrate_thresholds.py` proposes per-class, evidence-gated cutoffs into a candidate policy file and marks under-sampled classes `insufficient_evidence`; it never edits `taxonomy.yaml`. `src/scripts/hillclimb_eval.py` replays a candidate through the real `graph/routing.py` routers on held-out records and scores U = 1 − mean cost / review cost with risk guards (G1 overall wrong-auto upper bound, G2 per class, G3 replay fidelity) and an optional cost guard (G4), plus a paired-bootstrap ΔU against a baseline policy. Promoting a candidate to `taxonomy.yaml` is a separate reviewed change.
- **Scale hill-climb harness.** `src/scripts/stress_test.py` runs mock-LLM throughput, watcher backpressure, stale-claim, crash-recovery, SQLite-contention and provider-fault scenarios, gates on lost documents, duplicate rows, broken or missing audit entries and hijacked claims, and prints one `SCORE:` line.
- **A human review decision now flows back into the graph as data.** `POST /review/{doc_id}/resolve` accepts `resolution` (`approve_as_is` | `correct` | `reclassify` | `reject`; `reclassify` requires a class override, `doc_type` or `override_doc_type`, or a subtype change via `doc_subclass` / `contract_subtype`, and re-extracts under it) with `field_corrections`, `reviewer` (or the `X-Reviewer` header) and `reject_reason` (`not_a_legal_document`, `duplicate`, `unreadable`, `out_of_scope`, `wrong_matter`, `spam`, `other`). Approved or corrected fields go through the normal tail (`human_review` -> `compile_report` -> `catalog_write` -> `archive`) with no LLM call, so the report, catalog row, scores and `archived` audit event exist; the new `human_review -> compile_report` edge is gated on `review_decision == "human_applied"`, and a restart (no live checkpoint) enters at `compile_report` through the START router. Legacy `decision` + `disposition` requests still work: `approved`+`resume` re-extracts, `rejected`+`resume` rejects, `approved`+`complete` is `correct` (posted `extracted_data` replaces the parked fields) or `approve_as_is`. The manifest gains `human_label` (decision, resolution, final class, field corrections, a snapshot of the model output taken before the override, reviewer, UTC time, notes, reject reason), `extraction_source: "human"`, `reject_reason` and `file_location`; one `review_resolved` audit entry (actor = reviewer) precedes the tail. `extraction_confidence` stays the model's own value, never 1.0. **Legacy-visible changes** for API clients (The-Mailroom's resolve proxy): `disposition=complete` now archives through the graph tail, so its `complete` object keeps `stage`, `doc_type` and `archive_path`, adds `extraction_source: "human"`, `extracted_data` and `extraction_attempts`, and reports the model's `extraction_confidence` instead of the posted value or 1.0; the catalog row also carries `_report`; a resolve racing another in-flight resolve of the same document returns 409 (a resolve on a document no longer in review still returns 400). `review_resolve.complete_human_extraction` is no longer called by the API.

## Fixed

- **Grounded runs score against dataset labels only.** Post-hoc regex fills in `expected_fields` (source `posthoc` in `expected_fields_sources`) were scored as gold and gated the LLM judge (a corporate name `ACME INC.` became `entity_name: "ACM"`). Field scoring and the grounded judge input now use `observability.extraction_gt.labelled_expected_fields`, which keeps fields whose source is `hub`; routing coverage still sees every field.
- **Corporate `record_type` gold is the dataset label.** `catalog_expected_fields` set it from the subclass and fell back to the raw subclass name, so 283 of 450 corporate rows of dataset v9.3 expected a value outside the 5-value vocabulary (`board_resolution` is labelled `other`, `charter_amendment` is labelled `articles_of_incorporation`). The Hub `record_type` now wins; the subclass is used only when it names a vocabulary value. `communication_type` no longer falls back to the raw subclass either.
- **`"nan"` ground-truth cells are absence.** The literal `"nan"` / `"none"` / `"null"` / `"n/a"` (350 insurance rows carry `content_topic` / `sentiment_label` = `"nan"`) is no longer an expected value, so those rows emit no 0.0 topic or sentiment score.
- `observability.suite_scoring.score_document_payload` logs an unexpected Dojo exception (`score_document_payload_failed`) before falling back, instead of swallowing it; an unknown or non-extraction class still returns `None` quietly.
- HF pilot runs carry the row's `expected_stage` into `ground_truth`, so `stage_correct` is emitted.
- **`calibrate_field_scoring.py` runs on Python 3.11 again.** Its table printer nested same-type quotes inside an f-string, which only Python 3.12 accepts; the band label is now built before the `print`. The new root-import scan in `test_dojo_source.py` parses every file under `src/` and `tools/` and found this on the 3.11 CI image.
- **Audit remediation (#191-#201).**
  - Grounded field scoring now receives the real transcription (`result["doc_text"]`), not the pre-invoke snapshot that never carries it (#191), and `observability.scoring_wiring` is imported by `build_graph.py`, `run_pilot.py` and `run_hf_pilot.py` so field scoring, judge gating and the embedding rescue run on the calibrated `taxonomy.yaml` maps instead of Dojo package defaults (#192).
  - `GET /api/relations/mode` runs `mode_status()` off the event loop (#193).
  - `move_to_failed` has the audit A-20 collision protection `move_to_archive` already had, and both publish through the atomic link+unlink mover, so a concurrent mover or a re-failed `doc_id` can never overwrite preserved bytes; both call sites pass `doc_id` (#194). An abort between an intake claim and the state update resolves the claimed bytes by name (`bins.find_claimed_file`) instead of stranding the document in `processing/`. The abort path moves only the run's own recorded claim: when that claim is gone, or when the run never recorded one, it moves nothing (never another worker's same-named file), and the watcher's stale-claim reconcile recovers a genuinely stranded file. `find_claimed_file` keeps its name scan for read-only callers (`scan_fallback=False` turns it off). It records the real `failed/` path on the manifest, and `failed_file_path` prefers that recorded path only when its name is one this document's own move could produce (bare original name, its own review name, or a numbered fallback — another document's doc-suffixed name is rejected by the locator name gate). `_claimed_file_scan` tolerates a file vanishing mid-scan, and a review move on a filesystem without hard links publishes through a staged copy without clobbering.
  - `hf_corpus_loader`: every shard of a sharded config is loaded and concatenated (provenance records `shards` / `shards_total`), ground-truth filenames that match no corpus row are counted and logged, and a `content_sha256` mismatch on `load_corpus(verify=True)` logs loudly with the count — the mismatched rows are still returned, so scores against mutated text stay suspect by construction (verify=True is the caller's proof gate) (#195). The yearless-date scoring half of #195 is a scorer rule and is deferred to llm-dojo-scoring. The pipeline corpora are pinned to Hub revisions, and a pinned load resolves the revision to its commit sha and reads only that commit's files; a pin it cannot enforce raises instead of silently reading the Hub tip, `load_corpus` refuses to join two configs that resolved to different commits, and `run_hf_pilot`'s fallback loads pinned corpora through the same enforcing loader (#196).
  - legalbench trace scores keep a legitimate `macro_f1 == 0.0`, and a failed row no longer re-attaches the previous row's usage: usage is cleared at the start of each call and the runner reads it per row without writing agent state (#197).
  - `sliding_windows` returns each window's start position (overlap tail included), so intake section offsets translate document-absolute; each window is a contiguous slice of the source text, with no synthetic joiner (#199).
  - Lean cleanup (#200): removed the zero-caller `move_to_classified`, `load_taxonomy` and `SUPPORTED_EXTENSIONS`; the missing-`file_path` inbox fallback goes through `list_inbox_files()` so a `.meta` sidecar is never ingested as a document.
  - `ensure_score_configs` caches per-spec success and stops on a fetch failure, so a mid-loop Langfuse error no longer leaves a partial config set cached for the process lifetime; a later call retries only the missing specs (#201).

  `test_wheel_runtime_catalog` builds the wheel with this interpreter's own setuptools and wheel

- **PR #203 review round (human review).** A new review episode restarts `review_entered_at` (a replay keeps it); a live-resume abort keeps the corrected fields and moves the review file to `failed/`; `resume_from_review` validates reviewer fields on the stateless path too (409); a rejected Gmail document now gets a completion echo (neither the reject reason nor a failed-move error is disclosed); a re-review keeps the model's original snapshot.
- **PR #203 review round (volume).** Running claims refresh their `processing/` mtime at each node boundary, so a stale-claim sweep (even from another watcher process) leaves an advancing run alone; the catalog `updated_at` never moves backwards on a delayed write.
- **PR #203 review round (replay and calibration).** Policy replay picks the arbiter ruling typed for the selected class (new optional `ArbiterObservation.doc_type`; no collector sets it yet, so today's records stay untyped and an ambiguous untyped ruling is unobserved), rejects non-finite or unordered objective costs, groups extraction evidence by `doc_id`, and drops schema-invalid and hollow attempts from cutoff evidence. `calibrate_thresholds` re-checks the `low`/`high`/`judge_band_high` bands after every demotion.
- **PR #203 review round (review labels).** `export_review_labels` counts removed fields as corrections, keeps the parked attempt counts (`model_snapshot` now stores `classification_attempts` and `extraction_attempts`), exports the decision-lane verdict and route, validates a snapshot against the class it was extracted as, keeps parse failures as schema-invalid, and gives an unconfirmed rejection no sorter gold.
- **PR #203 review round (autoresearch gate).** A missing or empty `modes` line is not evidence for a `{records}` objective; the non-real check also applies to `guards_only` passes; a first candidate with no ΔU point estimate is a crash, never a baseline; an unformattable eval command is recorded as a crash.
- **PR #203 review round (pilot and stress).** `run_pilot`: an errored sample keeps the usage it billed in the totals and counts against its class; `--dataset hf` mock confidence never falls below `confidence.high`; colliding HF filenames take a content-hash suffix instead of draw order; `--source` matches an HF row's `source_corpus` (falling back to `dataset`), so a trace-source value that is not the row's corpus now selects nothing. `stress_test`: `db_contention` counts silently dropped audit events in `lost_audit_events`; `--db-docs-per-thread` must be at least 1.
- **Corpus `review_expected` strings parse as booleans, and the pilot survives a crashed sample.** `run_calibration_sweep.load_hf_docs` read the corpus string `"false"` as `True` (`bool("false")`); it now parses `true`/`false` text. `run_pilot.py` `summarize` / `print_rows` raised `KeyError` on a `status: error` row, hiding the failing document; the summary now reports `errors` (counted against `class_accuracy`) and the row prints its error.
- **A Boss ruling now covers only the conflict it ruled on.** `boss_escalation_node` stores `boss_conflict_fingerprint` (sha256 of the normalized `conflict_details`), and the judge/arbiter tail treats a conflict as adjudicated only when the current fingerprint matches. A different conflict that a retry extraction produces after the ruling, or after a human re-extract approval, now parks for review instead of archiving. States without the key (checkpoints from before this change) keep the old rule.
- **Policy replay no longer reuses an extraction for a subclass the sweep never extracted.** When the sweep collapsed a same-class candidate with another subclass, a route arriving with that subclass is now `unobserved` (`extraction_subclass_not_observed`). A default sweep (`--judge-attempts first`) also lists `judge_on_retry_attempts` in `diagnostics.unobserved_branches`, `hillclimb_eval` labels `LLM calls/doc` a lower-bound estimate, and the `planted_cutoff` docstring no longer claims a one-cell error bound.
- **A stopping watcher no longer claims new files.** A worker admitted before `Watcher.stop()` that reached `claim_file` only after the drain timeout could claim a document after the watcher lock was released, racing a replacement watcher. `stop()` now closes a claim gate before draining; a late worker leaves the file in the inbox (`claim_skipped_watcher_stopping`).
- **Audit writes survive heavy SQLite contention.** `write_audit_entry` retries `database is locked` on `BEGIN IMMEDIATE` with jittered backoff; each attempt re-reads the chain tail. At 128 writer threads failed operations drop from 119 to 0 with no broken chain.
- **Failed extraction chunks no longer archive silently, and chunk confidence is the weakest window's.** `BaseAgent.extract_chunked` (corporate record, correspondence, insurance) and the vendored `_SpecialistBase.extract_chunked` (contracts, merger) swallowed every per-chunk error and merged confidence as the MAX, so four windows `[0.98, ConnectionError, parse error, 0.4]` returned 0.98 with partial keys and auto-archived without a judge. A transient provider error in a window is now re-raised, so the node's `transient_error` routing retries it. A window that fails to parse (or raises a non-transient error) is counted: the result carries `_n_chunks` / `_failed_chunks` (underscore keys, ignored as non-public) and its confidence is capped strictly below the class `low` threshold, so routing retries or escalates. Merged confidence over the surviving windows is now the MIN, not the MAX. Single-window documents are unchanged. **Comparability:** long documents whose windows differ in confidence now score lower, and more of them reach retry or judge.
- **Sorter window disagreement now lowers confidence.** `_merge_sorter_reads` averaged only the windows that agreed with the winning class, so `[contract .99, corporate_record .99, correspondence .99]` merged to `contract .99`, and one `contract` window beside four `unknown` windows did too. Confidence is now the agreeing windows' mean times the share of non-unknown windows that agree (the first case reads 0.33), and when the winner holds fewer than half of all windows (unknown included) it is also capped strictly below its class `low` threshold. The vote vector rides the merged read as `_window_votes`. Single-window documents are unchanged. **Comparability:** over-budget documents with split window reads now reach retry or review where they used to continue.
- **A matter conflict no longer bypasses the extraction quality gates.** `after_extraction` sent `conflict_detected` straight to `boss_escalation` before the schema, hollow, coverage and confidence checks, and `after_boss` "approved" goes to `compile_report`, so a conflicted extraction with confidence 0.1 and an invalid schema was approved and archived with no retry, judge or review. The conflict check now runs at the point a sound extraction (schema valid, not hollow, coverage met, confidence at or above `low`) would otherwise go to `compile_report`; a failing extraction retries or escalates exactly as it would without a conflict. Return types and edge maps are unchanged.
- **Matter conflict detection no longer fires on formatting differences.** `_detect_conflict` compared normalized text for exact equality, so `Delaware` vs `State of Delaware` and `2024-01-05` vs `January 5, 2024` escalated to the Boss. Complete dates now compare as calendar dates (a bare year or month is not a date, and an ambiguous `01/02/2024` stays a text comparison); jurisdiction-like fields (`governing_law`, `jurisdiction`, `dispute_forum`, `venue`, court) ignore filler words (`state of`, `the`, `commonwealth`, `laws`) but still differ on any name part, so `Virginia` vs `West Virginia` and `State of New York` vs `State of New Jersey` remain conflicts; list fields are equal when one normalized set contains the other. The Dojo's `score_field` was tried and rejected for this: it scores `State of New York` vs `State of New Jersey` at 0.92, which a 0.9 cutoff would have hidden.
- **`_transient_decision` no longer claims the transient counters reset on success.** They never did, and must not: `first_pass_success` reads `transient_retries_<node>` to keep a document that needed a provider retry out of the first-pass KPI. The docstring now says so and a test pins it. Known limit: the budget is cumulative per node per run, so a node revisited several times (`retry_extract` through the arbiter loop) shares one budget of 2 transient retries.
- **Watcher concurrency is bounded.** Every watchdog event, startup-scan file and rescan tick used to start its own pipeline thread (400 inbox files ran 400 pipelines at once). Files now wait in a de-duplicated queue served by `watcher.max_concurrent_docs` workers (taxonomy.yaml, default 4; env `MAILROOM_MAX_CONCURRENT_DOCS`). `Watcher.stop()` discards files that have not started; they stay in the inbox. Needs a watcher/API restart.
- **Stale-claim reconcile no longer hijacks in-flight documents.** `claim_file` / `requeue_from_review` stamp the claim time (the hard link kept the upload's old mtime, so a document that waited in a backlog looked orphaned at once), and the watcher's periodic reconcile skips files this process is running or has queued. The separate `recover_processing.py --apply` CLI cannot see another process's in-flight set; it still relies on the claim time vs `--stale-minutes`, so run it with the watcher stopped.
- **Catalog writes are race-free upserts.** `write_matter_record` / `write_document_record` use one `INSERT ... ON CONFLICT DO UPDATE` (SQLite and PostgreSQL; other dialects keep the old path), so concurrent runs no longer fail with `UNIQUE constraint failed` and drop the stage update. Transient SQLite `database is locked` errors are retried with jittered backoff, and `busy_timeout` is now set before the WAL pragma (`SQLITE_BUSY_TIMEOUT_MS`, default 5000).
- A rejected review now resolves its interrupt checkpoint instead of leaking it, and a failed move to `failed/` is logged and recorded on the manifest (`file_location`) instead of swallowed.
- Resolving the same document twice no longer races: a resolve while another is in flight returns HTTP 409, and a late resolve (the document already left review) keeps the legacy 400 with the stage named (`archived`, not an enum repr); manifests are written atomically (temp file + `os.replace`).
- `human_review_node` no longer raises `UnboundLocalError` when the state has no `file_path`.
- **Every route into human review now names its cause.** `collect_review_causes` rebuilds the park reason from routing state (no ground truth or Langfuse scores needed) with new tokens `transient_exhausted`, `boss_conflict`, `arbiter_escalated`, `classification_arbiter_escalated`, `unknown_class`, `empty_document`, `unsupported_extraction`, `low_extraction_confidence`, `judge_incomplete`, `judge_error`, `retries_exhausted` and `chunk_failed`. `schema_invalid` and `guardrail` now fire from state. A judge `incomplete` verdict is `judge_incomplete`, no longer `reporting_incomplete`. Existing tokens are unchanged; The-Mailroom's `mailroom_ui/reconsideration.py` mirror needs the new ones.
- **Review tray is ordered by priority, then age.** `GET /review/queue` sorts by `pipeline/review_priority.py` (cause weights x class weight x age, from the new `review_queue:` block in `taxonomy.yaml`) and adds `priority`, `sla_breached` per item plus `oldest_age_hours` and `sla_breached` totals. Existing fields are unchanged.
- **Human resolutions become calibration labels.** `src/scripts/export_review_labels.py` turns manifests carrying a `human_label` into `RunRecord` JSONL (`gold.label_source="human"`) and prints wasted-review rate, correction rate, per-class agreement and field-edit counts. `Gold` gains optional `human_*` fields and `to_review_record` emits `human_decision`, `human_doc_type`, `human_doc_subclass`.
- **Resolving a review is safer at the edges (legacy-visible, additive).** A `complete` whose report/archive tail did not archive now records `review_approved` (not `review_completed`) with `detail.archived=false`, and the response adds `warning` and no `complete.archive_path`; `archive_path` comes only from this run's audit entries. `resolution` with any disposition (or none — `resume` is the default) and a non-empty `extracted_data` returns 400 (send `field_corrections` with `resolution=correct`; only the legacy `complete` with no `resolution` archives the posted object). A subtype/subclass change or clear over parked fields needs `resolution=reclassify` (400 for `approve_as_is`/`correct`); a legacy request with such a change is labelled `reclassify`, with its route unchanged. A legacy `complete` that drops a parked field is labelled `correct` with `human_label.removed_fields`. A cancelled resolve keeps the per-document lock until the graph thread ends. A direct `Command(resume)` with schema-invalid reviewer fields stays in review (`human_review_invalid`). Re-parked and aborted runs keep `extraction_source` and `human_label`, a rejection keeps the catalog subtype/subclass, and pipeline scores of a human-repaired run describe the model's extraction (`model_snapshot.parse_error`), not the repair.
- **Review age no longer resets on a note.** New `review_entered_at` (manifest, catalog `_review` block, `/review/queue` and `/documents` items) is set once per park; `age_hours`, `sla_breached` and the tray sort run from it, falling back to `updated_at` for older items.
- **A lost extraction window never archives.** `after_extraction` sends any extraction with `_failed_chunks > 0` to `retry_extract`, then `human_review`, whatever its confidence, and no judge or arbiter verdict clears it (previously only the confidence cap kept it out of the archive).
- **Watcher pool hand-off and cap are tight.** A name moves from queued to active in one critical section, so the rescan and the shutdown drain always see it, and workers that outlive `close()` still count against `MAX_CONCURRENT_DOCS`.
- `_run_coro` no longer times out after 10 s in the running-loop branch; it raised `TimeoutError` after a slow audit write had already committed (about 30 s worst case under `run_write_with_retry`, which now rejects `attempts < 1`).
- **Native pipeline diagnostics foundation** under `tools/pipeline-diagnostics/`: an installable `mailroom-diagnostics` inspection/check CLI, compiled-graph snapshots through the display exporter's shared graph helper, offline contract input, structural endpoint/reachability findings, and nested test/CI discovery. The draft workbench plan includes an ordered agent handoff and evidence contract. React, diagnostic HTTP serving, live events and calibration remain later milestones; this checkpoint changes no routing policy or model behavior. **Install change:** `pyproject.toml` `testpaths` now includes `tools/pipeline-diagnostics/tests`, so a bare `pytest` also needs `pip install -e tools/pipeline-diagnostics` (otherwise `test_console_script_is_installed` fails); vendored copies (the hub and `local-mailroom-sandbox`) need the same install.
