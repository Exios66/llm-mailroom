## Added

- **CI is CircleCI only, and it rejects leaked links.** The GitHub Actions workflows (the never-running daily Dojo auto-bump and the link guard) are removed; bump the Dojo pin by hand with `src/scripts/bump_dojo_scoring.py`. The new CircleCI job `no-session-links` fails when a commit or the PR description carries a claude.ai link, a `Claude-Session` trailer or a "Generated with Claude Code" footer. Commits follow the new `.gitmessage` template.
- **Staged interim ground truth: an opt-in, pinned overlay for labels the Hub does not publish yet (`observability/interim_gt.py`).** This ports the local-mailroom-sandbox interim label overlay (schema `mailroom-interim-labels/v1`) into the pipeline's GT layer.
  - **Loading.** The labels stay where the sandbox builds them, and a run pins the sha256 of their `MANIFEST.json` (`MAILROOM_INTERIM_GT_DIR` plus `MAILROOM_INTERIM_GT_SHA256`; set both or neither). Each class file is verified against the manifest. A mismatch raises `InterimOverlayError`.
  - **Merge.** `build_expected_fields` applies the truth labels (`gap_fill`, `derived`, `correction`) after the Hub catalog and before the post-hoc regex fill.
    - A label the Hub publishes supersedes the overlay.
    - A `correction` applies only while the Hub value equals the `hub_value` it corrected.
    - `disputed` labels are never applied.
    - Labels bind to the labelled document text.
    - A closed inventory field must hold a vocabulary value.
  - **Recording.** Applied fields carry source `interim:<status>`, which `labelled_expected_fields` scores as gold. The GT meta and HF pilot rows record `interim_gt` (overlay sha256 and per-field outcome). The HF pilot report header records the overlay identity, or `null`. `--resume` refuses a run whose overlay differs from the current one, so one report never mixes gold. Live-manifest rows key the overlay by `document_id` (Hub rows by `id`).
  - **Overlay rules fixed in the port.**
    - The sandbox overlay treated the CMS `claim_type` of `health` as a defect. Since #280 it is the correct gold, so a label that would change a CMS row's `claim_type` is rejected.
    - The sandbox derives `record_type` from the raw subclass, so 109 corporate labels (`charter_amendment`, `officer_certificate`, `board_resolution`, `indenture`, `subsidiary_list`) were outside the 5-token vocabulary. These are rejected.
  - **Checked offline** against the sandbox overlay and the cached Hub rows of revision `bc9eab2`, with a one-off script that is not committed:
    - all 1,111 overlay documents bind to their Hub text;
    - 1,003 labels apply: 484 corporate and 386 correspondence gap fills, 88 merger gap fills and 45 contract corrections. The overlay's 536 insurance `cms_source_table` `derived` labels no longer apply, because since #283 the pipeline derives `cms_source_table` from the Hub subclass itself and the Hub supersedes them with the same value;
    - 109 are rejected, and the Hub supersedes the rest.
  - Off by default: no score moves unless a run opts in. Tests: `test_interim_gt.py`.

- **Sync callers of the async storage share one long-lived event loop, so one SQLAlchemy engine per process instead of one per call.** Graph nodes, the watcher's triage catalog upsert, the relations sync surface, the warehouse export and the Gmail echo's audit read used to go through `asyncio.run`, and `storage/db.py` keeps one engine per event loop, so a document paid for about 20 loops, 20 engines and 31 SQLite connections (`docs/reports/evaluations/2026-11-17-graph-throughput-baseline.md`).
  - **How.** `storage/loop_bridge.py:run_sync` submits the coroutine to a daemon thread (`mailroom-storage-loop`) that runs one loop for the life of the process and blocks the caller until it finishes. Exceptions re-raise in the caller, and the coroutine runs in a copy of the caller's `contextvars` context, as it did under `asyncio.run`.
  - **Safe fallbacks.** A call from the loop's own thread (it would deadlock) runs on a fresh loop in a helper thread. After a fork, or if the loop thread died, a new loop starts. At interpreter exit the loop disposes its engine and stops, with a bound of about 4 s (2 s to dispose, 2 s to join).
  - **Kill switch.** `MAILROOM_DB_SHARED_LOOP=0` (also `false`, `off`, `no`) restores `asyncio.run` per call. One-shot CLIs and schema creation keep their own loops.

  - A `KeyboardInterrupt` or `SystemExit` raised inside the work reaches the caller without killing the loop thread.
  - An engine replaced on a long-lived loop (the resolved database URL changed) is now disposed.

- **Pluggable decision points: a decision model can refine any conditional route, off by default (`graph/decision_points.py`).** A slot in the new taxonomy `decision_points:` section (empty by default) binds a graph node to a backend registered with `register_decision_point_backend(name, fn)`; `fn(DecisionInput) -> DecisionOutcome | Mapping` gets the full `doc_text`, the node's key outputs and a read-only state view, and answers with a label, a confidence, review `causes`, a `model` and an optional `route_hint`. With a slot on, `build_graph()` wraps only that node: after it returns, the backend is consulted (bounded by the slot's `timeout_seconds`, default `run_limits.llm_call_timeout_seconds`, always capped by the run deadline; its own abandoned-thread cap, separate from the reviewer's and the gate's) and the outcome is written to the new state key `decision_outcomes[slot]`. A node that asked for a transient retry is not consulted, and its stale entry is dropped: its result is not usable, it will run again, and the router retries or parks it. A route rule `decision_point:<slot>` (the Phase 1 hook) applies the hint only when the outcome is `ok`, the hint is in the slot's `allow` (per class under `by_class`), its confidence meets `min_confidence`, and a hint to `human_review` carries causes; a rule never overrides the router's own park, a node's self-loop or a proposed verification gate (`retry_extract` for a lost window, an invalid schema or a hollow extraction; `judge_verify` and `arbiter` for an unsure or partial extraction; `boss_escalation` for a matter conflict): on the extraction side a hint can add scrutiny, never remove it. Classification routing stays open to hints by design: a slot on `classify`, `retry_classify` or `review_classify` may skip a classification retry, review or arbiter when its `allow` says so, and the extraction gates still run afterwards. The runtime taxonomy loader (`pipeline.config.load_config`) now refuses a duplicated mapping key anywhere in `taxonomy.yaml` (a duplicated slot or setting used to keep only its last value silently); YAML merge keys still work. A `malformed_answer` outcome records the validation message only for the outcome's own validation errors (`OutcomeValidationError`, a `ValueError`); any other exception from a backend-controlled object is recorded by its class name. A failure the backend declares itself (`status: unavailable` or `invalid`) is recorded as `backend_declined` with none of its own evidence, and logs and spans show a `route_hint` only when it names a destination the slot configures (`<unlisted>` otherwise), since both are backend-written text. `on_failure: fail_open` (default) turns a timeout, a transient provider error, a missing backend, an error or a malformed answer into no hint; `fail_safe` parks the document with `decision_point_unavailable` / `decision_point_invalid`. Outcomes that park show up as review causes `decision_point:<slot>:<cause>` (`collect_review_causes`, `format_causes`); a resolved human review clears every outcome. A malformed or graph-inconsistent section (unknown node or key, a hint outside the node's destinations, a self-loop in `allow`, a decision point on `human_review`, `intake`, `catalog_write` or `archive`) stops the watcher (`Watcher.start()`), the API (lifespan) and `build_graph()` with `DecisionPointConfigError`, so a bad section keeps the process from starting instead of failing every document. Each consultation is a `consult-decision-point` observation under the node's span, with slot, backend, node and status in its metadata (Langfuse tags are trace-level and immutable) and no document text; it is not in the display contract. `graph.build_graph._run_bounded` now delegates to the shared `graph.decision_points.run_bounded`, with the same behavior, messages and exception (`DecisionBackendTimeout`, still importable from `graph.build_graph`). **Loop safety:** each slot has `max_overrides` (integer 0 or more, default 1): how often it may redirect one document to a non-park destination, counted in the new state key `decision_override_counts` (never reset within a run). Past the budget the outcome is stored `capped` and the rule keeps the router's proposal (`decision_point_override_capped` warning), so a hint cycle across slots ends whatever the topology; the budgets of the active slots that can redirect (an `allow` in force, slot-wide when the slot is enabled or for an enabled `by_class` entry, with a destination other than `human_review`) may add up to 8 (the global cap, checked at build; `max_overrides: 0` for a record-only or park-only slot). Parks are exempt. With several slots on one node only the slot whose rule actually answers is charged, and none is charged when a route rule evaluated ahead of the slots (declared on the spec or registered before them) already takes the route. **Backends:** `backend:` is a registered name or an import spec `module.path:callable`, imported at startup and at each `build_graph()` for every active slot (a slot that is off for every class is never imported) (an import or attribute error, or an async callable, is a `DecisionPointConfigError`; `register_decision_point_backend` refuses coroutine functions too); a bare name that is not registered when the process starts logs `decision_point_backend_unregistered` once per slot per process (slot, backend, `on_failure`), and registering lazily stays allowed (the per-document missing-backend warning is also once per slot under `fail_open`). Backends receive deep copies of the state and handoff, and `label` text is never logged or put on a span (only its length). A backend's answer is read and validated inside the bounded call (a lazy mapping or an endless `causes` iterator is a timeout or `invalid`, never a hang; more than 8 `causes` is `invalid`), text fields are stored as exact `str` (a hostile `str` subclass cannot dodge the override budget), every returned `DecisionOutcome` (a subclass, or a plain one whose `evidence` dict the backend mutated after construction) is rebuilt and re-validated, a `causes` token with a trailing newline is `invalid`, a backend that raises `SystemExit` is `invalid`, and `timeout_seconds` must be above 0 and at most 3600. **Limits of this phase:** the stalled-thread cap (timed-out calls whose thread still runs; healthy in-flight calls never count, and the list can exceed 4 by at most the number of calls in flight when it fills) is one list shared by all slots, consult time counts inside the node's `_bounded` budget (after the node, capped by the run deadline), and there is no circuit breaker yet; they are planned for a later phase. `reset_compiled_graph()` also clears the decision-point rules, so call it only between runs. **Unchanged:** the default config (no wrapper, no rule, no new state key), routing, spans, the contract (`export_contract.py --check`), `register_decision_backend` and `register_extraction_gate` (they do not use slots yet and will move onto them later). ## Fixed

- **Ground-truth workbook edit consistency:** labels on a To Label sheet are the sole inputs for matching class-sheet cells, which are protected links. Class coverage and compact progress now read the same corrections. Date Audit is labelled as a build-time snapshot.

- **Best-attempt selection safety (#254):** reporting keeps the routing-approved latest attempt when an earlier candidate still needs review for confidence or oracle coverage. A live human approval/correction preserves the selected attempt’s model confidence, verdict and selection metadata alongside the human’s fields.

- **Chunk merge evidence grounding (#255):** a reasoning quote must occur in the window that asserted it before it can support a list claim or give a scalar evidence priority. Fabricated quotes no longer validate themselves.

- **A 200 response with no usable `choices` is a transient provider error, not a `TypeError` (#260).** OpenRouter answers HTTP 200 with `choices: null` and an `error` body when an upstream provider fails mid-generation. `retry_chat_completion` returned that response untouched, `BaseAgent._call_llm` (and the vision and PDF-transcriber paths) indexed `choices[0]`, and the resulting `TypeError` was not `is_transient_error`, so the judge's second pass parked the document as `judge_error` with only `judge verification failed (TypeError)` on record (the specialists, arbiter and boss shared the path). `retry_chat_completion` now validates every response and raises the new `llm.retry.EmptyChoicesError` for `choices` that is `None` or empty or a first choice with no `message`, with the provider's error code and message in the text; it is retryable and `is_transient_error` is true for it, so it gets the normal retry budget and, once spent, the nodes' transient path (`transient_exhausted` routing) instead of a hard failure. The exception is retryable only when the body carries no error code, 408, 429 or a 5xx code; a client-side code (400, 401, 402, 403, 404, 422 and the like) fails fast on the first attempt and takes the node's ordinary hard-fail branch with its `[cause: …]` text. A response object with no `choices` attribute at all is left alone. **Hard-fail audit text:** the `escalation_reason` / reasoning of the classify, re-classify, classification-arbiter, judge, arbiter and boss hard-fail branches now also carry `[cause: <first 300 chars of the exception message>]` after the unchanged `... failed (<ExceptionType>) ...` prefix (the arbiter reasoning fields append `: <message>`), so the cause is readable from run artifacts. The cause stays internal: the Gmail completion echo (text, HTML and digest) cuts the reason at `[cause:`, so exception text, which can carry paths, inputs or provider detail, never reaches the external sender; the manifest and audit log keep the full text. Tests: `src/tests/test_empty_choices_260.py`.
- **`markdown-it-py` floor raised to `>=4.0,<5` (#186).** 3.x has no cap on table-cell autocompletion (4.x ships `MAX_AUTOCOMPLETED_CELLS = 0x10000` in `rules_block/table.py`), so a crafted wide table in an intake Markdown document could balloon memory in `pipeline/text_cleaning.py`. Installs already on 4.x (the dev venv has 4.3.0) are unaffected; a 3.x environment must upgrade.

A default sweep (`--judge-attempts first`) also lists `judge_on_retry_attempts` in `diagnostics.unobserved_branches`, `hillclimb_eval` labels `LLM calls/doc` a lower-bound estimate, and the `planted_cutoff` docstring no longer claims a one-cell error bound.
- **A stopping watcher no longer claims new files.** A worker admitted before `Watcher.stop()` that reached `claim_file` only after the drain timeout could claim a document after the watcher lock was released, racing a replacement watcher. `stop()` now closes a claim gate before draining; a late worker leaves the file in the inbox (`claim_skipped_watcher_stopping`).
- **Audit writes survive heavy SQLite contention.** `write_audit_entry` retries `database is locked` on `BEGIN IMMEDIATE` with jittered backoff; each attempt re-reads the chain tail. At 128 writer threads failed operations drop from 119 to 0 with no broken chain.
- **Failed extraction chunks no longer archive silently, and chunk confidence is the weakest window's.** `BaseAgent.extract_chunked` (corporate record, correspondence, insurance) and the vendored `_SpecialistBase.extract_chunked` (contracts, merger) swallowed every per-chunk error and merged confidence as the MAX, so four windows `[0.98, ConnectionError, parse error, 0.4]` returned 0.98 with partial keys and auto-archived without a judge. A transient provider error in a window is now re-raised, so the node's `transient_error` routing retries it. A window that fails to parse (or raises a non-transient error) is counted: the result carries `_n_chunks` / `_failed_chunks` (underscore keys, ignored as non-public) and its confidence is capped strictly below the class `low` threshold, so routing retries or escalates. Merged confidence over the surviving windows is now the MIN, not the MAX. Single-window documents are unchanged. **Comparability:** long documents whose windows differ in confidence now score lower, and more of them reach retry or judge.
- **Sorter window disagreement now lowers confidence.** `_merge_sorter_reads` averaged only the windows that agreed with the winning class, so `[contract .99, corporate_record .99, correspondence .99]` merged to `contract .99`, and one `contract` window beside four `unknown` windows did too. Confidence is now the agreeing windows' mean times the share of non-unknown windows that agree (the first case reads 0.33), and when the winner holds fewer than half of all windows (unknown included) it is also capped strictly below its class `low` threshold. The vote vector rides the merged read as `_window_votes`. Single-window documents are unchanged. **Comparability:** over-budget documents with split window reads now reach retry or review where they used to continue.
- **A matter conflict no longer bypasses the extraction quality gates.** `after_extraction` sent `conflict_detected` straight to `boss_escalation` before the schema, hollow, coverage and confidence checks, and `after_boss` "approved" goes to `compile_report`, so a conflicted extraction with confidence 0.1 and an invalid schema was approved and archived with no retry, judge or review. The conflict check now runs at the point a sound extraction (schema valid, not hollow, coverage met, confidence at or above `low`) would otherwise go to `compile_report`; a failing extraction retries or escalates exactly as it would without a conflict. Return types and edge maps are unchanged.
- **Matter conflict detection no longer fires on formatting differences.** `_detect_conflict` compared normalized text for exact equality, so `Delaware` vs `State of Delaware` and `2024-01-05` vs `January 5, 2024` escalated to the Boss. Complete dates now compare as calendar dates (a bare year or month is not a date, and an ambiguous `01/02/2024` stays a text comparison); jurisdiction-like fields (`governing_law`, `jurisdiction`, `dispute_forum`, `venue`, court) ignore filler words (`state of`, `the`, `commonwealth`, `laws`) but still differ on any name part, so `Virginia` vs `West Virginia` and `State of New York` vs `State of New Jersey` remain conflicts; list fields are equal when one normalized set contains the other. The Dojo's `score_field` was tried and rejected for this: it scores `State of New York` vs `State of New Jersey` at 0.92, which a 0.9 cutoff would have hidden.
- **`_transient_decision` no longer claims the transient counters reset on success.** They never did, and must not: `first_pass_success` reads `transient_retries_<node>` to keep a document that needed a provider retry out of the first-pass KPI. The docstring now says so and a test pins it. Known limit: the budget is cumulative per node per run, so a node revisited several times (`retry_extract` through the arbiter loop) shares one budget of 2 transient retries.
- **Watcher concurrency is bounded.** Every watchdog event, startup-scan file and rescan tick used to start its own pipeline thread (400 inbox files ran 400 pipelines at once). Files now wait in a de-duplicated queue served by `watcher.max_concurrent_docs` workers (taxonomy.yaml, default 4; env `MAILROOM_MAX_CONCURRENT_DOCS`). `Watcher.stop()` discards files that have not started; they stay in the inbox. Needs a watcher/API restart.
- **Stale-claim reconcile no longer hijacks in-flight documents.** `claim_file` / `requeue_from_review` stamp the claim time (the hard link kept the upload's old mtime, so a document that waited in a backlog looked orphaned at once), and the watcher's periodic reconcile skips files this process is running or has queued. The separate `recover_processing.py --apply` CLI cannot see another process's in-flight set; it still relies on the claim time vs `--stale-minutes`, so run it with the watcher stopped.
- **Catalog writes are race-free upserts.** `write_matter_record` / `write_document_record` use one `INSERT ... ON CONFLICT DO UPDATE` (SQLite and PostgreSQL; other dialects keep the old path), so concurrent runs no longer fail with `UNIQUE constraint failed` and drop the stage update. Transient SQLite `database is locked` errors are retried with jittered backoff, and `busy_timeout` is now set before the WAL pragma (`SQLITE_BUSY_TIMEOUT_MS`, default 5000).
- A rejected review now resolves its interrupt checkpoint instead of leaking it, and a failed move to `failed/` is logged and recorded on the manifest (`file_location`) instead of swallowed.
- Resolving the same document twice no longer races: a resolve while another is in flight returns HTTP 409, and a late resolve (the document already left review) keeps the legacy 400 with the stage named (`archived`, not an enum repr); manifests are written atomically (temp file + `os.replace`).
- `human_review_node` no longer raises `UnboundLocalError` when the state has no `file_path`.
- **Every route into human review now names its cause.** `collect_review_causes` rebuilds the park reason from routing state (no ground truth or Langfuse scores needed) with new tokens `transient_exhausted`, `boss_conflict`, `arbiter_escalated`, `classification_arbiter_escalated`, `unknown_class`, `empty_document`, `unsupported_extraction`, `low_extraction_confidence`, `judge_incomplete`, `judge_error`, `retries_exhausted` and `chunk_failed`. `schema_invalid` and `guardrail` now fire from state. A judge `incomplete` verdict is `judge_incomplete`, no longer `reporting_incomplete`. Existing tokens are unchanged; The-Mailroom's `mailroom_ui/reconsideration.py` mirror needs the new ones.
- **Review tray is ordered by priority, then age.** `GET /review/queue` sorts by `pipeline/review_priority.py` (cause weights x class weight x age, from the new `review_queue:` block in `taxonomy.yaml`) and adds `priority`, `sla_breached` per item plus `oldest_age_hours` and `sla_breached` totals. Existing fields are unchanged.
- **Human resolutions become calibration labels.** `src/scripts/export_review_labels.py` turns manifests carrying a `human_label` into `RunRecord` JSONL (`gold.label_source="human"`) and prints wasted-review rate, correction rate, per-class agreement and field-edit counts. `Gold` gains optional `human_*` fields and `to_review_record` emits `human_decision`, `human_doc_type`, `human_doc_subclass`.
- **Resolving a review is safer at the edges (legacy-visible, additive).** A `complete` whose report/archive tail did not archive now records `review_approved` (not `review_completed`) with `detail.archived=false`, and the response adds `warning` and no `complete.archive_path`; `archive_path` comes only from this run's audit entries. `resolution` with any disposition (or none — `resume` is the default) and a non-empty `extracted_data` returns 400 (send `field_corrections` with `resolution=correct`; only the legacy `complete` with no `resolution` archives the posted object). A subtype/subclass change or clear over parked fields needs `resolution=reclassify` (400 for `approve_as_is`/`correct`); a legacy request with such a change is labelled `reclassify`, with its route unchanged. A legacy `complete` that drops a parked field is labelled `correct` with `human_label.removed_fields`. A cancelled resolve keeps the per-document lock until the graph thread ends. A direct `Command(resume)` with schema-invalid reviewer fields stays in review (`human_review_invalid`). Re-parked and aborted runs keep `extraction_source` and `human_label`, a rejection keeps the catalog subtype/subclass, and pipeline scores of a human-repaired run describe the model's extraction (`model_snapshot.parse_error`), not the repair.
- **Review age no longer resets on a note.** New `review_entered_at` (manifest, catalog `_review` block, `/review/queue` and `/documents` items) is set once per park; `age_hours`, `sla_breached` and the tray sort run from it, falling back to `updated_at` for older items.
- **A lost extraction window never archives.** `after_extraction` sends any extraction with `_failed_chunks > 0` to `retry_extract`, then `human_review`, whatever its confidence, and no judge or arbiter verdict clears it (previously only the confidence cap kept it out of the archive).
- **Watcher pool hand-off and cap are tight.** A name moves from queued to active in one critical section, so the rescan and the shutdown drain always see it, and workers that outlive `close()` still count against `MAX_CONCURRENT_DOCS`.
- `_run_coro` no longer times out after 10 s in the running-loop branch; it raised `TimeoutError` after a slow audit write had already committed (about 30 s worst case under `run_write_with_retry`, which now rejects `attempts < 1`).
- **Native pipeline diagnostics foundation** under `tools/pipeline-diagnostics/`: an installable `mailroom-diagnostics` inspection/check CLI, compiled-graph snapshots through the display exporter's shared graph helper, offline contract input, structural endpoint/reachability findings, and nested test/CI discovery. The draft workbench plan includes an ordered agent handoff and evidence contract. React, diagnostic HTTP serving, live events and calibration remain later milestones; this checkpoint changes no routing policy or model behavior. **Install change:** `pyproject.toml` `testpaths` now includes `tools/pipeline-diagnostics/tests`, so a bare `pytest` also needs `pip install -e tools/pipeline-diagnostics` (otherwise `test_console_script_is_installed` fails); vendored copies (the hub and `local-mailroom-sandbox`) need the same install.
