## Added

- **Native audit workbench integration** (`tools/pipeline-diagnostics/`): the React panel follows a recorded run or looks up audit documents independently, with paginated discovery, refresh, row/addendum attempts, hash links and explicit verification limits. Authenticated read-only API routes and `mailroom-diagnostics audit --json` support both current per-event storage and the optional unified schema. Missing stores remain missing; raw audit detail and unknown journal payloads are excluded from responses. This viewer does not migrate storage or activate the unfinished audit writer/scoring rollout. Failure ids read from stored rows are shown without control characters and capped at 128 characters, and sub-rows of another document that name a record's parents are read separately (at most `limits.foreign_attempts`, 50), so they always fail `attempt-doc-mismatch` and can never exhaust the document's own attempt cap. Verification also fails closed like the foundation verifier: a row event, attempt stage or attempt trigger outside the writer's lists (`unknown-event`, `unknown-stage`, `unknown-trigger`) and a parent reference whose stage or attempt number disagrees with its sub-row (`attempt-ref-mismatch`) fail even with a valid hash, and a missing `audit_attempts` or `audit_addenda` table is `unverified`, never `verified`. The demo seeder resolves symlinks in its protected store paths before honouring `--force`.

- **Unified audit storage foundation, opt-in** (roadmap M2/M3 plus a storage-scope-limited M4 verifier; `src/storage/audit_migrate.py`, `src/audit/`). This lands the storage layer only: no graph node, terminal writer, trace sink or scoring path calls it yet, and the roadmap stays unfinished.
  - New tables: `audit_attempts`, `audit_addenda`, `audit_meta`, `audit_trace_io` and `audit_log_legacy`. An explicitly migrated `audit_log` holds one row per document with a unique `doc_id` and one global `seq`; before that it keeps the current per-event shape.
  - **The migration is never automatic.** The first `ensure_schema()` call in a process (the API's own startup does not make it) logs `audit_migration_pending` and changes nothing unless `MAILROOM_AUDIT_MIGRATE=1` (SQLite and Postgres alike). A fresh database still creates the new tables, but the marker, the unique indexes and the legacy copy wait for the explicit step. Ordinary runs keep writing the current `audit_log` through `write_audit_entry`.
  - `python -m storage.audit_migrate` runs it deliberately (SQLite needs no knob; Postgres always requires `MAILROOM_AUDIT_MIGRATE=1` after quiescing writers), under the `audit_log:chain` lock and in one transaction: SQLite is backed up to `<db dir>/backups/` with owner-only permissions, every `audit_log` row is copied byte-for-byte into `audit_log_legacy`, counts and a column digest are checked, and only then is `audit_log` emptied, given its unique indexes and recorded in `audit_meta` (`migrated_at`, `legacy_rows`, `legacy_tail_hashes_sha256`). Postgres also takes `LOCK TABLE audit_log IN ACCESS EXCLUSIVE MODE` before the deciding count. A mismatch aborts with nothing changed; a second run is a no-op.
  - `--rollback` renames the new tables to `*_v2_<timestamp>` and restores the previous release's `audit_log` from `audit_log_legacy` (rows written since stay in the renamed tables).
  - The current writer and readers stay working through `event_log_model()`: after a deliberate migration they append to and read `audit_log_legacy`; before it they use the current `audit_log` with unchanged order, sequences and hashes. The per-document write lock key is now `audit_doc:<doc_id>` (was `audit_log:<doc_id>`), so on Postgres a writer from the previous release no longer excludes one from this release for the same document: stop old-release writers before starting this release (SQLite is unaffected, `BEGIN IMMEDIATE` serializes every writer).
  - `write_terminal_row()`/`write_addendum()` (unused by the pipeline yet) write the unified row, attempt sub-rows and addenda with v2 hashes byte-identical to the dojo's `archive_entry_hash`; they refuse with `AuditMigrationPending` until the marker exists. Both retry transient SQLite lock contention (`BEGIN IMMEDIATE` → `database is locked`) through the shared PR #203 wrapper, replaying the whole transaction in a fresh session with bounded jittered backoff; non-lock database errors fail fast.
  - `audit.verify.verify_audit_db()` checks the global row chain, attempt references/membership and hashes (and that every stored event, attempt stage and trigger is one the writer accepts), per-document addendum chains, the legacy per-document chain and stored trace-I/O hashes. It reports pending rows/sinks as uncollected rather than claiming proof, and `scripts/verify_audit_chains.py --json` exposes it. It is scope-limited, not memory-bounded: the offline verifier materializes those tables in memory, so cost grows with the rows checked.
  - Tests: `src/tests/test_audit_migrate.py` against `src/tests/fixtures/audit/legacy_audit.db` (rebuilt by `src/scripts/build_legacy_audit_fixture.py`), `test_audit_writer.py`, `test_audit_verify.py` and the default-off regression in `test_audit_log.py`. Postgres DDL is compiled for the `postgresql` dialect; the migration runs on SQLite.

- **`run_pilot.py` runs on real documents from the pinned HF corpus.** `--dataset {samples,hf}` (with `--per-class`, `--seed`, `--split`) builds the pilot set from `Lucius-Morningstar/mailroom-dataset` through `hf_corpus_loader.load_corpus` at the pinned revision and writes each document's full text into the run's base dir. In `--mock`, a checkout without `docs/examples/samples/manifest.csv` falls back to it; `--real` needs `--dataset hf` named explicitly. Corpus rows count as real samples.
- **Guarded autoresearch loop.** `experiments/autoresearch/objectives.yaml` registers each hill-climb objective (`thresholds`, `scale`, `review`) with its metric, direction, minimum gain, guards and the evidence a kept change needs; `src/scripts/autoresearch_gate.py` runs the core guards (compileall, affected tests, the experiment gate, the display contract, the changelog check) before the objective's eval, then keeps, discards or rejects the iteration (exit 0 / 3 / 2, 1 on crash) and logs it to `experiments/autoresearch/state/`. The `thresholds` objective also requires the paired-bootstrap ΔU 95% interval to have a positive lower bound. Protocol: `experiments/autoresearch/instructions.md`.
- **Threshold calibration and offline route replay.** `src/schemas/run_record.py` defines a per-document `RunRecord` (every sorter, reviewer, extraction, judge and arbiter attempt, gold kept out of the routing state); `src/scripts/run_calibration_sweep.py` collects them with every sorter, reviewer and extraction branch run per document; the arbiter and Boss nodes are never run, and by default the judge runs only on extraction attempt 1 (`--judge-attempts all` judges every attempt) (`--real` refused unless `MAILROOM_ALLOW_REAL=1`). `src/scripts/calibrate_thresholds.py` proposes per-class, evidence-gated cutoffs into a candidate policy file and marks under-sampled classes `insufficient_evidence`; it never edits `taxonomy.yaml`. `src/scripts/hillclimb_eval.py` replays a candidate through the real `graph/routing.py` routers on held-out records and scores U = 1 − mean cost / review cost with risk guards (G1 overall wrong-auto upper bound, G2 per class, G3 replay fidelity) and an optional cost guard (G4), plus a paired-bootstrap ΔU against a baseline policy. Promoting a candidate to `taxonomy.yaml` is a separate reviewed change.
- **Scale hill-climb harness.** `src/scripts/stress_test.py` runs mock-LLM throughput, watcher backpressure, stale-claim, crash-recovery, SQLite-contention and provider-fault scenarios, gates on lost documents, duplicate rows, broken or missing audit entries and hijacked claims, and prints one `SCORE:` line.
- **A human review decision now flows back into the graph as data.** `POST /review/{doc_id}/resolve` accepts `resolution` (`approve_as_is` | `correct` | `reclassify` | `reject`; `reclassify` requires a class override, `doc_type` or `override_doc_type`, or a subtype change via `doc_subclass` / `contract_subtype`, and re-extracts under it) with `field_corrections`, `reviewer` (or the `X-Reviewer` header) and `reject_reason` (`not_a_legal_document`, `duplicate`, `unreadable`, `out_of_scope`, `wrong_matter`, `spam`, `other`). Approved or corrected fields go through the normal tail (`human_review` -> `compile_report` -> `catalog_write` -> `archive`) with no LLM call, so the report, catalog row, scores and `archived` audit event exist; the new `human_review -> compile_report` edge is gated on `review_decision == "human_applied"`, and a restart (no live checkpoint) enters at `compile_report` through the START router. Legacy `decision` + `disposition` requests still work: `approved`+`resume` re-extracts, `rejected`+`resume` rejects, `approved`+`complete` is `correct` (posted `extracted_data` replaces the parked fields) or `approve_as_is`. The manifest gains `human_label` (decision, resolution, final class, field corrections, a snapshot of the model output taken before the override, reviewer, UTC time, notes, reject reason), `extraction_source: "human"`, `reject_reason` and `file_location`; one `review_resolved` audit entry (actor = reviewer) precedes the tail. `extraction_confidence` stays the model's own value, never 1.0. **Legacy-visible changes** for API clients (The-Mailroom's resolve proxy): `disposition=complete` now archives through the graph tail, so its `complete` object keeps `stage`, `doc_type` and `archive_path`, adds `extraction_source: "human"`, `extracted_data` and `extraction_attempts`, and reports the model's `extraction_confidence` instead of the posted value or 1.0; the catalog row also carries `_report`; a resolve racing another in-flight resolve of the same document returns 409 (a resolve on a document no longer in review still returns 400). `review_resolve.complete_human_extraction` is no longer called by the API.

## Fixed

- **A 200 response with no usable `choices` is a transient provider error, not a `TypeError` (#260).** OpenRouter answers HTTP 200 with `choices: null` and an `error` body when an upstream provider fails mid-generation. `retry_chat_completion` returned that response untouched, `BaseAgent._call_llm` (and the vision and PDF-transcriber paths) indexed `choices[0]`, and the resulting `TypeError` was not `is_transient_error`, so the judge's second pass parked the document as `judge_error` with only `judge verification failed (TypeError)` on record (the specialists, arbiter and boss shared the path). `retry_chat_completion` now validates every response and raises the new `llm.retry.EmptyChoicesError` for `choices` that is `None` or empty or a first choice with no `message`, with the provider's error code and message in the text; it is retryable and `is_transient_error` is true for it, so it gets the normal retry budget and, once spent, the nodes' transient path (`transient_exhausted` routing) instead of a hard failure. A response object with no `choices` attribute at all is left alone. **Hard-fail audit text:** the `escalation_reason` / reasoning of the classify, re-classify, classification-arbiter, judge, arbiter and boss hard-fail branches now also carry `[cause: <first 300 chars of the exception message>]` after the unchanged `... failed (<ExceptionType>) ...` prefix (the arbiter reasoning fields append `: <message>`), so the cause is readable from run artifacts. Tests: `src/tests/test_empty_choices_260.py`.
- **Sandbox RCA fixes (Exios66/local-mailroom-sandbox#300).** Found by experiments and review on the sandbox's vendored snapshot:
  - **Opt-in: a confident retry after a judged attempt can be judged again (#241). Off by default.** `after_retry_extraction_gated` and `judge_should_run` share `routing.retry_rejudge_due`: when an earlier attempt was judged and `judge_pass_count < judge_max_passes`, the retry goes to `judge_verify` whatever its self-reported confidence. Before, a retry reporting 1.0 archived unjudged. This only happens when the new threshold `judge_rejudge_retry` is `true` (globally or per class under `by_class`). It ships `false`, so the default routing is unchanged until the judge is calibrated (#242). With it on, documents that are judged and then retried spend one more judge call, and possibly an arbiter call, and a replayed retry that routing sends to `judge_verify` without a recorded judge pass is `unobserved` (`judge_not_observed_on_attempt_2`). No node or edge is added.
  - **The completeness and correctness judges no longer score pipeline metadata (#242, partial).** `confidence`, `reasoning` and `_`-prefixed keys are left out of the judge's expected-field list and of the extraction it sees, for the in-graph judge and the offline callers. The judge prompt is unchanged. Calibrating verdicts against Dojo scores per class needs real-model runs, and per-class verdict/score agreement reporting in the judge eval is not added; both stay open on #242.
  - **A total chunk failure is parked as `chunk_failed` (#249).** When every window fails, both chunked extractors now return `_n_chunks` and `_failed_chunks` with the parse error, as a partial failure already did.
  - **`sliding_windows` never exceeds its budget (#243).** The overlap tail is reserved inside the budget (overlap clamped to `budget // 2`), so long documents get slightly more, slightly smaller intake and sorter windows. Windows stay contiguous slices with exact offsets.
  - **Replay cutoff evidence skips attempts that lost chunks (#244),** as it already skipped schema-invalid and hollow ones: routing retries all three at any confidence.
