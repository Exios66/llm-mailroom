## Fixed

- **Insurance `claim_type` is the product line, never a CMS table token (#174 §2).** `CLAIM_TYPE_DESCRIPTION` and the extract-node insurance handoff (`specialist_handoff`) told the specialist to put `pde` / `inpatient` / `outpatient` / `carrier` in `claim_type`. The Dojo has scored those 0 since llm-dojo-scoring#93, because every CMS row's line is `health`. Both now teach the closed `INSURANCE_PRODUCT_LINES` only. `enrich_extraction` maps a CMS table token, whether from the model or backfilled from the sorter subclass, to `health` through the new `normalize_claim_line`. The post-hoc extraction GT does the same. The sorter subclass keeps the CMS table tokens. A guard test pins `INSURANCE_PRODUCT_LINES` to the Dojo's. On the sandbox's production slice 100 r2, this cause alone accounts for 12 of the 22 insurance wrong archives.
- **The correspondence `communication_type` description no longer labels any inbox message `email` (#269).** `COMMUNICATION_TYPE_DESCRIPTION` (`langchain_agents/doc_inventories.py`) said "Enron-style inbox messages are email". It is embedded in the correspondence JSON schema (`specialist_agents.CORRESPONDENCE_SCHEMA`), where it outranks the prompt, so a press release, memo or notice that arrived as an email was typed `email` (sandbox: 6 of 7 gold-typed non-email correspondence documents, 3 `press_release`, 2 `memo`, 1 `notice`). It now says to type the content, not the carrier: a memo, letter, notice, demand, press release or meeting request sent, forwarded or pasted in an email takes that type, and `email` is for ordinary email correspondence with no other form inside it. The eight allowed values and their order are unchanged. The correspondence `specialist_handoff` carried the same "inbox text is email" sentence and says the same now. **Not changed here:** the frozen correspondence prompt (`llm/frozen_v1/correspondence_specialist.txt`, sha-pinned by `lineage.json`) still contains "Enron-style inbox -> email", as do the Dojo's correspondence templates; both need their own re-freeze or upstream change. This changes what the model is told, so extraction output for correspondence will move on a real model; the mock LLM returns each sample's gold and cannot show it. Tests: `test_doc_inventories.py`.
- **A decision-reviewer backend error is recorded, not filed as a reviewer that answered nothing (#268).** In `_decision_review_classify`, a non-transient backend error (a 403 content filter, a 401 auth failure, another non-retryable 4xx, a malformed body) was logged and then treated as `raw = None`, indistinguishable from a real no-answer. The document still parked with `reviewer_causes: [reviewer_unavailable]` (from `decide_review`) and went to the classification arbiter, but nothing on the record said why. It now also sets `error_message` to `decision reviewer error: <ExceptionClass>: <first 200 characters of the message>` and appends the same text to `escalation_reason`. It does not set `transient_error`, so there is no retry, and the transient and timeout branches are unchanged. **Routing is unchanged:** a failed decision review still goes to the classification arbiter, then a person, as a transient-exhausted or timed-out review does; a document continues to extraction only if the arbiter accepts a class above its cutoff, and then the node clears this `error_message` so the catalog does not file it as the document's escalation reason. No new edge or cause token; `collect_review_causes` already reports `reviewer_unavailable` from `reviewer_causes`. No downstream schema or span change. Tests: `test_decision_review_node.py`.
- Evidence matching requires complete lexical spans, avoiding positive phrases matched inside hyphenated or longer words. CUAD QA sampling checks paragraph lengths before selection and materializes full text only for selected titles.
- Run accounting keeps a call whose usage reports `input_tokens=0` with positive `output_tokens` (a fully cached prompt); the `or` fallback treated the zero as missing and dropped the whole call, completion count included (`pipeline/limits.py:record_usage`).
- Ground-truth workbook: a cell is clipped by UTF-16 units, as Excel counts them, not by code points, so a value of many emoji can no longer exceed Excel's 32,767-character cell limit.
- The sorter reviewer's hard-fail `escalation_reason` no longer carries the exception text in the part the Gmail completion echo shows: it names the exception type and puts the text behind `[cause: ...]`, which the echo cuts, so provider error text (for example a 401 body) is not sent to the document's sender (`graph/build_graph.py:review_classify_node`, #260). Our own `MAILROOM_LLM_FREE_ONLY` guardrail text (a plain `RuntimeError` that starts with that name) stays visible so the free-only explanation (HUB-043) still reaches the sender. The manifest and audit log keep the full cause.

## Added

- **Editable ground-truth label workbook** (`tools/gt-label-workbook/build_gt_workbook.py`). It builds an `.xlsx` of the pinned corpus's `ground_truth` config. Each document class gets a value column and a status column for every field the Dojo scores that the dataset labels for that class (a field with no label yet is highlighted); a pipeline field the dataset never carries for a class (for example insurance `claim_checklist`) gets no column and is listed on the README sheet. A `Date Audit` sheet lists every date label with the year, month and day it states (flagged NO YEAR, NO DAY/MONTH or UNPARSEABLE), and a `Summary` sheet counts coverage with live formulas. It reads the Hub through `pipeline.hf_corpus_loader` (read-only) or offline from parquet, and never writes to Hugging Face. `openpyxl` joins the `dev` extra. Review round: `--revision` is now resolved to a commit sha through the Hub API (an unknown revision exits non-zero) and the parquet files are read from `resolve/<sha>/`, with the sha recorded on the README sheet; corporate records gain `filing_number` (the per-row missing set matches the Dojo's `unlabeled_fields`); `communication_type`, `cuad_family` and `merger_consideration` are derived from the subclass, not gaps; `sanitize_text` also replaces U+FFFE, U+FFFF and lone surrogates; external text files use `quote(id, safe="")` names so they cannot leave the texts folder. Readability: frozen id column and header, wrapped fixed-height rows, identity / links / subclass / value+status column order, grouped hidden helper columns, a legend. A fresh database still creates the new tables, but the marker, the unique indexes and the legacy copy wait for the explicit step. Ordinary runs keep writing the current `audit_log` through `write_audit_entry`.
  - `python -m storage.audit_migrate` runs it deliberately (SQLite needs no knob; Postgres always requires `MAILROOM_AUDIT_MIGRATE=1` after quiescing writers), under the `audit_log:chain` lock and in one transaction: SQLite is backed up to `<db dir>/backups/` with owner-only permissions, every `audit_log` row is copied byte-for-byte into `audit_log_legacy`, counts and a column digest are checked, and only then is `audit_log` emptied, given its unique indexes and recorded in `audit_meta` (`migrated_at`, `legacy_rows`, `legacy_tail_hashes_sha256`). The per-document write lock key is now `audit_doc:<doc_id>` (was `audit_log:<doc_id>`), so on Postgres a writer from the previous release no longer excludes one from this release for the same document: stop old-release writers before starting this release (SQLite is unaffected, `BEGIN IMMEDIATE` serializes every writer).

  - `audit.verify.verify_audit_db()` checks the global row chain, attempt references/membership and hashes (and that every stored event, attempt stage and trigger is one the writer accepts), per-document addendum chains, the legacy per-document chain and stored trace-I/O hashes. It reports pending rows/sinks as uncollected rather than claiming proof, and `scripts/verify_audit_chains.py --json` exposes it. It is scope-limited, not memory-bounded: the offline verifier materializes those tables in memory, so cost grows with the rows checked.
